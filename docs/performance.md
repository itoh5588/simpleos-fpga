# 速度測定

FPGAのCPUの命令の速さと、PCとのUARTの往復時間、OSの操作にかかる時間をまとめる。比べる相手は書籍のエミュレーター（`emu.py`）である。

## 命令の速さ

### 測定方法

`tools/bench_loop.py` で、同じプログラムをエミュレーターとFPGAで実行する。内側のループは `DEC R0` と `JPNZI` の2命令を524,288回くり返し、外側のループ（R1）でこれを数回くり返してHALTする。`--mmu` を付けると、0xFFF00に恒等変換のページ表（論理ページnを物理ページnへ）を置き、PTをそこへ向けて、CRを0x80000000にしてからループに入る。OSがタスクを動かすときと同じく、MMUが有効な状態になる。

```sh
python3 tools/bench_loop.py --book <os_book_code> --emu [--mmu]          # 外側2回、約210万命令
python tools/bench_loop.py --book <os_book_code> --port COM5 [--mmu]     # 外側40回、約4,200万命令
```

HALTの時点でR0とR1が0であることを確かめ、ループを最後まで実行したことを確認する。FPGAでは、`X` で起動してから `H` を受けるまでの時間を測る（UARTの往復の約1msを含む）。

### 結果

| 条件 | エミュレーター | FPGA | 倍率 |
|---|---|---|---|
| MMU無効 | 毎秒26万命令 | 毎秒428万命令 | 約17倍 |
| MMU有効 | 毎秒16万命令 | 毎秒85万命令 | 約5倍 |

- エミュレーター：WSL2のPython 3.12、AMD Ryzen 5 3600。PCのCPUによって変わる。
- FPGA：ui_clk 81.25MHz。1命令あたりの平均は、MMU無効で約19サイクル、MMU有効で約96サイクル。

### MMU有効で遅くなる理由

`emu.py` は命令ごとにページ表を主記憶から読み直す。FPGAのCPUも同じ動作をするため、MMUが有効だと命令ごとに16バイトのページ表を読む。DDR3アダプターが保持できるのは16バイトの1ラインだけで、ページ表（0xFFF00）と命令（0x80000）は別のラインになるので、命令ごとにDDR3からの読出しがおよそ2回起きる。DDR3から読むと平均20サイクル程度かかる（[回路の構成](architecture.md#ddr3アダプター)）。

## UARTの往復時間

PCホストとFPGAの1回のやり取りにかかる時間（中央値）。SYSCALLのたびにこの往復が起きる。

| 操作 | 待ち時間タイマー16ms・115200bps | 1ms・115200bps | 1ms・3Mbaud |
|---|---|---|---|
| `R` 1バイト | 16.0ms | 1.0ms | 1.0ms |
| `G`（64バイト） | 22.0ms | 6.5ms | 1.0ms |
| `R` 256バイト | 38.2ms | 24.0ms | 2.0ms |
| `W` 256バイト | 32.0ms | 24.0ms | 2.0ms |

標準の設定は、待ち時間タイマー1ms・3Mbaud（[ハードウェア](hardware.md#usb-uart変換器の設定)）。

## OSの操作にかかる時間

`tools/check_board.py` で、標準の設定（1ms・3Mbaud）で測った時間。

| 操作 | 時間 |
|---|---|
| 主記憶を0にする（`Z`、1MiB） | 0.07秒 |
| 16KiBの書込みと読戻し | 0.1秒 |
| OSのロードから「Welcome to Simple OS!」まで | 0.2〜0.3秒 |
| `ls`、`date`、`reg` | 各0.1秒 |
| `taskexec pagefault.bin` | 0.4秒 |
| `exec hello.bin`、`exec mul.bin` | 各0.2秒 |
| `exec dump.bin` | 0.5秒 |

OSの操作は、文字の表示やキー入力のたびにSYSCALLでPCと往復するため、命令の速さよりもUARTの往復の回数で時間が決まる。エミュレーターはSYSCALLを同じプロセスの中で処理するので、表示が中心の操作ではFPGAの方が速いとは限らない。

## 速くする余地

- ページ表をCPUの中に保持し、PTの変更やページ表への書込みがあったときだけ読み直せば、MMU有効でもMMU無効に近い速さが見込める。`emu.py` と同じ結果になることは、既存の回帰試験で確かめられる。
- DDR3アダプターの読出しバッファを複数ラインにすれば、命令とデータ・ページ表の読出しが互いに追い出し合わなくなる。
- 文字列の表示をFPGA側でまとめて送るなど、SYSCALLごとの往復を減らすには、プロトコルの変更が必要になる。
