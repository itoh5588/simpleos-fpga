# 用語集

このリポジトリの文書に出てくるFPGAと基板まわりの用語を、分野ごとにまとめる。伊藤明雄著『れがしーなOS達: FPGAで動かす PDP-11と2.11BSD』の付録F「用語集」を元に、このプロジェクトに合わせて書き換え、用語を加えた。括弧内は、その用語を主に使う章である。

## FPGAと回路データ

- **FPGA**：Field-Programmable Gate Arrayの略。製造後に内部の回路を書き換えられる部品である。中には、小さな真理値表として働く論理の素子（LUT）、値を覚えるフリップフロップ（FF）、ブロックRAMなどが多数並び、その間を結ぶ配線も切り替えられる。回路データを読み込むと、それらの素子と配線が決まり、一つの回路として働く。このプロジェクトではこの上にSimple OSのCPUを作る。（[回路の構成](architecture.md)）
- **XC7S50**：Arty S7-50に載っているFPGAの型番。AMD（旧Xilinx）のSpartan-7系列に属する。Hardware Managerでは `xc7s50_0` と表示される。（[ビルドと書込み](build.md)）
- **構成（コンフィギュレーション）**：FPGAに回路データを読み込ませ、内部の回路を決める操作。電源を切ると構成は消えるので、電源を入れるたびに構成し直す。PCからJTAGで送る方法と、基板上の構成フラッシュから読む方法がある。（[ビルドと書込み](build.md)）
- **bitstream（ビットストリーム）**、`.bit`：FPGAに読み込ませる回路データ。このプロジェクトでは `build/os/simpleos_os_board.bit` をVHDLソースからビルドする。OSのイメージ（`os.bin`）とは別物で、`os.bin` は起動後にPCホストがUARTで主記憶へ送る。（[ビルドと書込み](build.md)）
- **構成フラッシュ**：基板上にある、回路データを保存しておく不揮発メモリー。電源を入れるとFPGAはここから自動で構成される。Arty S7ではQuad-SPI接続のフラッシュで、Micron MT25QL128（16MB）を使う。OSのファイルは保存しない。（[ビルドと書込み](build.md)）
- **MCS**、`.mcs`：構成フラッシュへ書く内容を、番地付きの文字で表したファイル。`.bit` からVivadoの `write_cfgmem` で作る。`board/flash.tcl` が自動で作る。（[ビルドと書込み](build.md)）
- **SPI、Quad-SPI**：部品同士をクロック線とデータ線でつなぐ同期式の通信方式。構成フラッシュはこの方式でFPGAとつながる。Quad-SPIはデータ線を四本使う形で、このプロジェクトの `SPIx1` は一本だけ使う設定を指す。（[ビルドと書込み](build.md)）
- **MODEジャンパー（JP1）**：Arty S7で、電源投入時に構成フラッシュから構成するかを決めるジャンパー。付けておくと、電源を入れるだけで構成フラッシュの回路が動く。（[ハードウェア](hardware.md)）
- **DONE**：構成が終わったことを示すFPGAの信号。Arty S7では同じ名前のLEDが点灯する。（[ビルドと書込み](build.md)）

## 開発ツール

- **Vivado**：AMDのFPGA開発ツール。VHDLからの合成、配置・配線、ビットストリーム生成と、基板の構成や構成フラッシュの書込みを行う。このプロジェクトではVivado 2022.1を、コマンドを書いたTclファイルを渡すバッチモード（`vivado -mode batch -source ...`）で使う。（[ビルドと書込み](build.md)）
- **Hardware Manager**：Vivadoの中で、つないだ基板のFPGAを操作する機能。このプロジェクトでは `board/program_cpu.tcl` や `board/flash.tcl` がTclのコマンドで使う。GUIのHardware Managerが基板を開いていると、これらのスクリプトは基板を使えない。（[ビルドと書込み](build.md)）
- **hardware server**（`hw_server`）：Hardware Managerの裏で、JTAGケーブルとのやり取りを受け持つプログラム。ほかのVivadoが基板を使っている間は、基板が見えないことがある。（[ビルドと書込み](build.md)）
- **Tcl**：Vivadoを操作するコマンド言語。`board/` の `.tcl` ファイルは、MIGの生成、ビルド、構成、構成フラッシュの読み書きの手順を書いたもの。（[ビルドと書込み](build.md)）
- **IP**：Vivadoが設定に従って生成する、出来合いの回路。このプロジェクトではMIGだけを使う。（[回路の構成](architecture.md#migの設定)）
- **Vivado Simulator**：Vivadoに付属するシミュレーター。`xvhdl` でVHDLを解析し、`xelab` で一つのシミュレーションにまとめ、`xsim` で実行する。（[試験](testing.md)）
- **テストベンチ**：シミュレーションのために、試したい回路に入力を与え、出力を確かめる回路。ファイル名は `tests/tb_*.vhd`。（[試験](testing.md)）

## 回路の設計とビルド

- **VHDL**：回路の構造と動作を文章で記述する言語。プログラムのように見えるが、書いた内容は順に実行されるのではなく、同時に動く回路になる。このプロジェクトの回路は `rtl/` にVHDLで書いてある。（[回路の構成](architecture.md)）
- **合成**：VHDLの記述から、FPGAの素子で作れる論理回路を求める工程。（[ビルドと書込み](build.md)）
- **配置・配線**：合成した回路の各部分をFPGAのどの素子に置き、どの配線で結ぶかを決める工程。（[ビルドと書込み](build.md)）
- **クロック**：回路の動作の拍子を刻む信号。回路の多くはクロックの変わり目に合わせて値を更新する。このプロジェクトのCPUは81.25MHzで動く。（[回路の構成](architecture.md#クロックとリセット)）
- **MMCM、PLL**：入力のクロックから、周波数の違うクロックを作る部品。FPGAの中にいくつか備わり、それぞれ近くのクロック領域に属する。このプロジェクトでは、自前のMMCMで12MHzから100MHzと200MHzを作り、MIGは内部のMMCMとPLLでDDR3用のクロックを作る。（[回路の構成](architecture.md#クロックとリセット)）
- **クロック領域**：FPGAを区切った領域。入力端子からMMCMへクロックを専用の経路で送るには、両者が同じクロック領域になければならない。R2の100MHzを使わないのはこのため。（[回路の構成](architecture.md#クロックとリセット)）
- **タイミング解析、WNS、WHS**：配置・配線した回路で、信号が決められた時間内に届くかを調べる工程。WNSは次のクロックまでに間に合う条件の最も小さい余裕、WHSは値を保持する条件の最も小さい余裕である。負なら条件を満たしていない。`board/build_os.tcl` は、負のときbitstreamを作らない。（[ビルドと書込み](build.md)）
- **XDCファイル**：Vivadoに与える制約を書いたファイル。FPGAの端子番号と信号の対応、入出力の電気規格、クロックの周期などを記す。このプロジェクトでは `board/artys7_os.xdc`。（[ハードウェア](hardware.md)）
- **LVCMOS33**：FPGAの入出力端子に設定する電気規格の一つで、3.3Vで動く信号を表す。JCのUART信号はこの規格なので、USB-UART変換器も3.3Vのものを使う。（[ハードウェア](hardware.md)）

## DDR3とメモリー制御

- **DDR3、DDR3L**：主記憶に使うRAMの規格。DDR3Lはその低電圧版で、Arty S7-50はDDR3L（256MB）を載せている。このプロジェクトでは、Simple OSの主記憶1MiBをこのRAMに置く。（[回路の構成](architecture.md)）
- **MIG**：Memory Interface Generator。DDR3を読み書きする制御回路を生成する、VivadoのIP。DDR3の初期化、タイミング合わせ、リフレッシュを受け持ち、利用者には単純な読み書きの口（UI）を見せる。設定は `board/mig_artys7.prj`。（[回路の構成](architecture.md#migの設定)）
- **ui_clk**：MIGが利用者側の回路に供給するクロック。DDR3のクロック（325MHz）の1/4の81.25MHzで、このプロジェクトのCPUもこれで動く。（[回路の構成](architecture.md#クロックとリセット)）
- **キャリブレーション（較正）**：MIGが起動時に行う、DDR3との信号のタイミング合わせ。終わると `init_calib_complete` が1になり、LD2が点灯する。（[回路の構成](architecture.md)）
- **BL8**：DDR3の1回の読み書きで、データ線を8回続けて使う形（バースト長8）。Arty S7の16bit幅のDDR3では16バイトになり、MIGの1コマンドに当たる。（[回路の構成](architecture.md#ddr3アダプター)）
- **参照クロック、IDELAYCTRL**：入力信号の遅延を細かく調整する素子（IDELAY）を較正する回路がIDELAYCTRLで、200MHzの参照クロックを必要とする。（[回路の構成](architecture.md#クロックとリセット)）
- **XADC**：FPGAに内蔵されたA/D変換器で、チップの温度も測れる。MIGは温度による遅延の変化を補正するのに使う。（[回路の構成](architecture.md#migの設定)）

## 基板と接続

- **Arty S7-50**：Digilentが販売する、XC7S50を載せた評価基板。主記憶に使うDDR3Lメモリー、構成フラッシュ、Pmod端子、PCとつなぐUSB端子を備える。（[ハードウェア](hardware.md)）
- **Pmod、JC**：PmodはDigilentが定めた、周辺基板をつなぐコネクタの規格である。12ピンのPmodは6ピンずつ二段に並び、各段の5番目がGND、6番目が3.3V電源になっている。JCはArty S7上のPmod端子の名前で、このプロジェクトではJCにUSB-UART変換器をつなぐ。（[ハードウェア](hardware.md)）
- **JTAG**：もとは基板の検査用に定められた接続方式（IEEE 1149.1）で、FPGAでは回路データの書込みや動作の観察に使う。クロック、モード、データ入力、データ出力の四本の信号で部品とやり取りする。Arty S7では基板上のUSB変換部品（FT2232）がこの信号を作るので、PCとはUSBケーブル一本でつながる。JTAGで構成した回路は電源を切ると消える。（[ビルドと書込み](build.md)）
- **UART**：文字のデータを一ビットずつ順に送る方式。送る向きごとに一本ずつ信号線を使い（自分のTXから相手のRXへ）、送受信を同時に行える。送る側と受ける側はクロックを共有しないので、速度（bps）や文字の形（8N1）を両方で合わせておく。このプロジェクトでは3Mbaud、8N1である。（[ハードウェア](hardware.md)）
- **BREAK**：UARTの信号線を、1文字の長さより長くLowにし続けること。このプロジェクトでは、20ビット時間以上のBREAKで回路をリセットする。（[UARTプロトコルとSYSCALL](protocol.md)）
- **USB-UART変換器**：PCのUSBとUARTの信号を相互に変換する部品やケーブル。PCからはCOMポート（Linuxでは `/dev/ttyUSB0` など）に見える。FTDI社のFT232Rはその代表的な変換チップである。（[ハードウェア](hardware.md)）
- **待ち時間タイマー（latency timer）**：FTDIの変換器が、少量の受信データをPCへ渡すまで待つ時間。既定は16msで、このプロジェクトでは1msにする。（[ハードウェア](hardware.md#usb-uart変換器の設定)）
- **TX、RX、GND**：TXは送信、RXは受信の信号線、GNDは信号の基準電位を共有する線である。一方のTXを相手のRXにつなぐので、基板と変換器の間では向きが交差する。（[ハードウェア](hardware.md)）
- **COMポート**：Windowsがシリアル通信の装置に付ける名前。変換器ごとにCOM5のような番号が割り当てられ、PCホストにはこの番号を指定する。（[PCホスト](host.md)）
- **usbipd**：WindowsにつないだUSB機器を、WSLのLinuxから使えるようにするツール（usbipd-win）。WSLのVivadoからJTAGを使うときに、ArtyのUSBをWSLへ接続する。（[ビルドと書込み](build.md)）
